■ 概要
Pianist は、業務アプリ等の GUI 操作が必須な設定作業を、Profile 単位で
実行する Extended モジュールです。autokey_template の進化版で、
FlexProfile / Linear 両方のプロファイル経由での実行と、Script Menu
からの単発実行に対応します。

v0.2.x の app 版は廃止され、本モジュールに統合されました。Profile の
作成・編集は Fabriq Studio 側に一任しています。

■ UI ポリシー
すべての操作はマウスクリックで行います。キーボードショートカットは
持たせていません。理由は:
  - キーボードは SendKeys でターゲットアプリへ送る専用チャネル
  - Run 中の race / 迷子キー事故防止

■ 実行経路
1. Profile CSV 経由 (推奨)
   profiles/*.csv の行に
     extended/pianist/pianist.ps1, Segment=<segment_name>
   を指定すると、kernel が pianist_list.csv を Segment フィルタで
   絞り込み、対応する 1 profile を直接 GUI に流し込んで実行する。

2. Script Menu からの単発実行
   ダッシュボード > [Execute Module] > ManualWorks > Pianist
   pianist_list.csv の Enabled=1 全行が候補としてプルダウンに
   並び、operator が選択して実行する。

■ pianist_list.csv の列
  Enabled      : 実行候補に含めるか (1/0)
  ProfileName  : profiles/ 配下のフォルダ名 (1 ProfileName = 1 phase 構造)
  Group        : 表示用グループ名 (Sample / Production など、自由記述)
  Description  : 候補一覧での説明文
  Segment      : Profile CSV 経由で指定する segment 名 (Import-ModuleCsv が
                 自動フィルタする)

■ Profile 構造
modules/extended/pianist/profiles/<profile_name>/
  pianist.json       : メタデータ (label / description / target_app / default_phase)
  procedure.csv      : 操作手続 (Phase x Step マトリクス)
  values.csv         : 設定値プール ($VarName で procedure から参照、wide format)
  shortcuts.csv      : 起動先ショートカット集 (v1.0 では参照のみ、UI 側未実装)
  instructions/      : Phase 手順テキスト
    <PhaseID>.txt    : 手順説明 (since v1.4.0 section marker 対応)
  screenshots/       : [Samples] section が参照する見本画像置き場
                       (Screenshot アクションのエビデンス出力先ではなく、
                        author 提供の参照画像用)

■ instructions/<PhaseID>.txt の section format (since v1.4.0)
各 Phase の手順テキストを section marker で区切れる:

  [RPA]
  Run Phase で自動実行される操作の説明。
  手順タブ上段「RPA でやること」に表示される。

  [Manual]
  operator が目視 / クリック / 確認で実施する手順。
  手順タブ下段「手動でやること」に表示される。

  [Variables]
  # この Phase の Copy Values で表示したい変数を明示宣言。
  # 1 行 1 変数 or 空白 / カンマ区切りで複数列挙可。# はコメント。
  AdminUser, AdminPass
  LicenseKey

  [Samples]
  # author 提供の見本画像ファイル名 (空白区切りで任意のキャプション)
  # since v1.5.0: [Samples] タブにサムネイル表示、クリックで拡大ビューワ
  # 画像ファイルは <profile>/screenshots/ 配下に配置すること
  # ※ Screenshot アクション (operator 実行時のエビデンス自動撮影) や
  #    Capture-ScreenEvidence 出力とは別概念。author 側で事前に置く
  #    「こういう画面が出たら成功」「ここをクリック」等の参考画像。
  before.png  パスワード変更画面の初期状態
  after.png   変更完了後の画面

後方互換: section marker が **1 つもない** プレーンテキストファイルは
全文を [Manual] として表示する (v1.3.x 以前のサンプルは無修正で動作)。

[RPA] が無い場合は procedure.csv の Step 一覧を fallback 表示する
(operator が「Run Phase で何が起きるか」を最低限把握できる)。

[Variables] で宣言された変数は procedure.csv の $VarName 自動抽出と
union され、Step で使わないが Copy Values で出したい変数 (操作者が
読み上げる license key、別アプリへ paste する社内連絡先など) を
明示的に Phase ごとに紐づけられる。

■ values.csv の構造 (since v1.1.0: wide format)
hostlist.csv と同じ「1 行 = 1 ホスト、列 = 変数」の縦横配置。

  NewPCName,<Var1>,<Var2>,<Var3>,...,<VarN>
  *,共通値1,共通値2,共通値3,...,共通値N
  PC-001,個別値1,,個別値3,...,
  PC-002,,個別値2,,...,個別値N

解決規則:
  1. 現在のターゲット PC 名 (env: SELECTED_NEW_PCNAME) で行を検索
  2. 同 Key 列で PC 固有行に値あり -> それを採用
  3. 空欄 or PC 固有行なし -> NewPCName='*' (or 空欄) の default 行で補完
  4. どちらも空 -> 変数未定義 ($VarName のまま procedure に残る)

暗号化:
  - セル単位で値の頭に "ENC:<Base64>" を埋め込むだけで透過復号 (hostlist.csv と同じ規約)。
  - 別途の Encrypted 列は **不要**。Fabriq Studio 側で行/セル単位の暗号化 UI を提供
  - master passphrase は fabriq 本体と共有

列名の制約:
  - 列名は [A-Za-z_][A-Za-z0-9_]* (英字またはアンダースコアで始まる英数字)
  - "NewPCName" は予約 (行キー専用、変数として参照不可)
  - 上記以外、列数と列名は profile ごとに自由。案件に応じて Studio で増減

後方互換 (legacy long format):
  - v1.0.x までの "Key,Value,Encrypted,Note" 形式の values.csv も自動判別して読み込み可
  - 新規 profile は wide format で書く

■ procedure.csv の列
  PhaseID     : 同 ID の行群が 1 Phase に集約される (例: P01, P02...)
  PhaseLabel  : Phase ヘッダーバーに表示するラベル
  Color       : Phase ヘッダーの色
                Blue / Green / Yellow / Orange / Red / Purple / Cyan / Pink / Gray
  StepNo      : Phase 内の通番 (昇順実行)
  Action      : アクション種別 (後述)
  Value       : アクション引数 ($VarName で values.csv の値に展開)
  Wait        : Step 完了後の追加待機 (ms)。WaitWin では timeout
  Note        : Step preview とログに表示するメモ
  ※ v1.0 にあった `Screenshot` 列は v1.5.0 で撤去 (vestigial、コードから
    一度も参照されなかったため)。Phase 単位の見本画像参照は
    instructions/<PhaseID>.txt の [Samples] section を使う

■ アクション 10 種
  Open         : URL / exe / ms-settings: などを既定で起動
                 (since v1.1.1) パス内のスペースを自動判定し、引数なしで
                 あれば引用符不要で渡せる:
                     Open  C:\Program Files\Foo\bar.exe
                 引数を渡したい場合は Windows 標準慣習どおりパスを引用符
                 で囲むこと:
                     Open  "C:\Program Files\Foo\bar.exe" /flag1 /flag2
  WaitWin      : ウィンドウタイトル <Value> を含むものが現れるまで待機
  AppFocus     : ウィンドウタイトル <Value> にフォーカス (必須パターン)
  Type         : SendKeys でテキスト送信 ($VarName 展開)
  Key          : SendKeys で特殊キー送信 ({ENTER}, {TAB}, ^v, %{F4})
  Wait         : 指定 ms 待機
  Copy         : 値をクリップボードへ
  Paste        : 値をクリップボードへ -> Ctrl+V
  Screenshot   : 画面キャプチャを fabriq evidence へ保存
  Prompt       : MessageBox で operator 介入待ち

■ Phase 設計ルール
operator が Phase ボタンをクリックした瞬間、フォーカスは Pianist に
移ります。そのため、既存ウィンドウを操作する Phase は必ず Step 1 に
AppFocus を置いてください。
  例:
    P02,...,1,AppFocus,Notepad,...
    P02,...,2,Type,...
  例外:
    - 新規ウィンドウを Open で起こす Phase は AppFocus 不要
    - WaitWin は内部で SetForegroundWindow を呼ぶので兼ねる

■ 実行モデル (operator 視点)
  1. ダッシュボード or Profile CSV から起動
  2. (候補が複数なら) プロファイル選択ダイアログでひとつ選ぶ
  3. fabriq の確認ダイアログで [Y] を押して GUI を開く
  4. 左右の <, > ボタンで Phase を行き来する
  5. 各 Phase 画面で:
     - [Run Phase]      : Phase の全 Step を順次実行
     - [Screenshot]     : 手動でエビデンスを取得
     - [Phase Status]   : OK / Warning / Error / Skip + Note を記録
     画面中央の TabControl (since v1.4.0、3 タブ構成 since v1.5.0):
     - [Procedure]   タブ: RPA (上段、auto-executed by Run Phase) +
                           Manual (下段、performed by operator) の 2 段組表示。
                           instructions/<PhaseID>.txt の [RPA] / [Manual]
                           section を解釈して section ごとに描画
     - [Samples] タブ    : author 提供の見本画像サムネイル一覧 (since v1.5.0)。
                           クリックで原寸ズーム表示ビューワをモードレス
                           で開く (Pianist 本体は引き続き操作可能)。
                           画像ソースは <profile>/screenshots/ フォルダ、
                           参照は instructions/<PhaseID>.txt の [Samples]
                           section。タブ見出し "Samples (N)" の N は当該
                           Phase の見本画像数。画像欠損時は
                           "(missing) <filename>" の placeholder で表示。
                           operator が撮るエビデンスとは別概念
     - [Values]      タブ: この Phase の参照変数 + [Show all] トグル時は
                           全変数。各行の [Copy] ボタンで値 (ENC: 復号後) を
                           クリップボードへ転送。タブ見出し "Values (N)" の
                           N は参照変数の数
  6. 最後の Phase で > が "Done" ボタンに変化
  7. Done を押すと kernel に ModuleResult を返却
     -> 通常モジュールと同じく実行履歴 / HTML チェックリスト /
        evidence summary に並ぶ

■ 二軸のステータス
各 Phase は 2 軸の独立した状態を持ちます:
  Auto   : Run Phase の自動実行結果
           NotRun / Running / Success / Partial / Error
  Manual : operator 判定
           Unset / OK / Warning / Error / Skip

両方を Phase 画面下部にバッジ表示。

■ 集計ロジック (Module 終了時)
  Manual 内訳に基づき集計:
    Error >= 1                                -> Status=Error,    Verified=$false
    Warning >= 1 or Unset >= 1                -> Status=Partial,  Verified=$null
    全て OK / Skip                             -> Status=Success,  Verified=$true
  Cancel された場合 (X ボタン or キャンセル確認):
    Status=Cancelled

  ModuleResult を return すると kernel が:
    - Write-ExecutionHistory で logs/history/execution_history.csv に追記
    - SessionID / WorkerName / KanriNo / PCName を自動補完
    - Capture-ScreenEvidence で前後スクショ取得
    - エラー時は Invoke-SafeCommand で try/catch + ERROR 履歴

■ ベストプラクティス
  - Phase 最初の Step は AppFocus (規約必須)
  - 日本語や記号を Type すると IME に弱いので Paste を優先
  - ウィンドウ待機は WaitWin で行い、Wait の固定スリープに依存しない
  - 機密値は Studio で ENC: 暗号化して values.csv に
  - instructions/<PhaseID>.txt に operator が読む手順を記述
  - 重要な分岐点で Prompt アクションを置き、operator に目視確認させる

■ 制限・既知事項 (v1.0.0)
  - UIA / AutomationId 操作は非対応 (将来検討)
  - 録画機能なし
  - IF / LOOP 等の制御構文なし。線形シーケンスのみ
  - Mouse 系アクションなし (座標クリックは冪等性なしのため非採用)
  - 並列実行不可 (1 Phase 実行中は他全ボタン disable)
  - Phase 状態は session-only (Pianist 終了でリセット、永続化なし)
  - Tools (Values の ad-hoc Copy/Type, Shortcuts ランチャ) は v1.0 で非搭載。
    必要なら values.csv を Studio で開いて手動コピー、ショートカットは
    System Launcher 等で代替。

■ デバッグのコツ
  - 下部 Log に各 Step の実行結果が時系列で出る
  - Phase ヘッダーの色 / Steps preview / Auto バッジで動作確認
  - WaitWin / AppFocus が見つからない場合: ウィンドウタイトルが日本語
    Windows と英語 Windows で異なる可能性。Studio 側で profile 編集時に
    実環境のタイトル文字列に合わせること

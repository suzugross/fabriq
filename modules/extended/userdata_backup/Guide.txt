■ 概要
任意のファイル / ディレクトリの **portable backup + restore** を担う
試作モジュールです。printer_backup と同じ backup フォルダ規約・
manifest 中心設計・hostlist 駆動の解決ロジックを踏襲しています。

将来、複数の backup モジュール（printer_backup / userdata_backup /
今後追加）を **単一統合 backup モジュール**にまとめる計画があるため、
manifest 構造を printer_backup と parallel に保っています。

  [Backup Userdata]  (userdata_backup.ps1)
    userdata_backup_list.csv の各 enabled 行を 1 entry として、
    backup フォルダに robocopy でまるごとコピー。

  [Restore Userdata] (userdata_restore.ps1)
    manifest.json を読み込み、各 entry を robocopy で逆方向に
    復元。per-entry OnConflict（skip / overwrite / rename）を尊重。

■ 出力／入力ディレクトリ

  modules/extended/userdata_backup/
    backup/
      <OldPCname>/                   ← $env:SELECTED_OLD_PCNAME 優先、
                                       未設定時は $env:COMPUTERNAME
        <yyyy_MM_dd_HHmmss>/
          manifest.json              ← schemaVersion=1 単一の真実源
          _restore_notes.txt
          entries/
            01/
              data/                  ← robocopy で複製した中身
                ...
              entry_log.txt          ← 当該 entry の robocopy ログ
            02/
              ...

■ 制御 CSV

  [userdata_backup_list.csv] (N rows、backup 対象を 1 行 1 entry で指定)
    Enabled         : 0=この行を skip / 1=有効
    SourcePath      : バックアップ対象パス。%USERPROFILE% などの
                      環境変数を含めて OK（backup 実行時に展開して
                      manifest に絶対パスで記録）
    Recurse         : 1=サブディレクトリ含めて再帰コピー / 0=トップのみ
                      （ファイル指定の場合は無視）
    ExcludePattern  : セミコロン区切りの除外パターン。
                      末尾 / のものはディレクトリ名（robocopy /XD）、
                      それ以外はファイル名（/XF）に振り分け。
                      例: "*.tmp;Cache/;~$*"
    OnConflict      : restore 時の挙動。skip / overwrite / rename
                      （rename = 既存を .bak_yyyyMMdd_HHmmss にリネーム）
    IncludeAcl      : 1=ACL（NTFS 権限）も保存（robocopy /COPYALL）
                      0=データ・属性・タイムスタンプのみ（/COPY:DAT）
                      ※ cross-PC で SID が異なる場合、ACL は復元失敗
                        または意図せぬ権限になる可能性あり。既定 0
    Description     : 表示用メモ

  [userdata_backup_config.csv] (1 row、restore 時の override)
    Enabled         : 0=モジュール skip / 1=有効
    SourcePcName    : 空欄=$env:SELECTED_OLD_PCNAME 駆動。値=その PC 名を強制
    BackupTimestamp : 空欄=最新を自動選択。値=その timestamp フォルダを指定
    Description     : 表示用メモ

■ Restore 時のソース解決優先順位
1. CSV SourcePcName が空でなければ → それを使用（明示 override）
2. $env:SELECTED_OLD_PCNAME が空でなければ → それを使用（hostlist 駆動）
3. どちらも空 → エラー abort（"select a host or set CSV"）

タイムスタンプも同様:
1. CSV BackupTimestamp が値ありならそれを使用
2. 空なら指定 PcName 配下の manifest.collectedAt 最新を auto-select

■ 前提条件
・管理者権限が必要です（robocopy /B backup mode、ACL 操作）
・robocopy.exe が PATH に存在すること（Windows Vista 以降は常に存在）

■ AutoPilot
AutoPilot モードでは Confirm-ModuleExecution を skip して即実行します。
__ASYNC__ 経路（kernel 3.3.0+ DefaultAsync=true）で Skip ボタン中断可能。

■ Post-Apply Verification

  [Backup]
  ・manifest.json / _restore_notes.txt の存在＋サイズ非ゼロ
  ・manifest.json が schemaVersion=1 / manifestType="fabriq-userdata-backup"
  ・各 entry の data/ フォルダ存在確認

  [Restore]
  ・各 entry の resolvedPath が target PC 上に存在することを Test-Path で確認

■ 制約・注意事項
・**Cross-user 復元は out of scope**（同一ユーザ前提）。`%USERPROFILE%`
  は backup 実行時のユーザに展開されて manifest に記録される。restore 時の
  ユーザが異なる場合は手動でパス調整が必要
・**ACL 保存は既定 OFF**。cross-PC で SID が異なるため、復元後の権限が
  意図と違う可能性。要件があればエントリ単位で IncludeAcl=1
・**EFS 暗号化ファイル**は robocopy 既定では復号できないものは skip
  される。完全 raw 保存が必要なら robocopy /EFSRAW の opt-in 列を
  将来追加する余地あり（未実装）
・**シンボリックリンク / Junction** は robocopy 既定挙動（target を辿る）。
  リンクとして保存したい場合は /SL or /SJ の追加が必要（未実装）
・**ロック中のファイル** は robocopy /B（バックアップモード）で
  読み取り試行するが、それでも開けないファイルは skip + warning
・**EFS / lock failed / large file** はすべて warning に降格し他 entry の
  処理を阻害しない

■ Manifest スキーマ（fabriq-userdata-backup schemaVersion=1）

  schemaVersion, manifestType, backupVersion, fabriqKernelVersion,
  collectedAt, computerName (=OldPCname), hardwareUniqueId,
  osVersion, osArch,
  counts: { entry, file, dir, missingSource },
  sizes:  { totalBytes },
  items: { entries: [
    { id, sourcePath, resolvedPath, isDirectory, recurse,
      excludePattern, onConflict, includeAcl,
      fileCount, dirCount, byteCount,
      backupSubpath, robocopyExitCode, status, reason }
  ]},
  warnings: []

printer_backup の manifest と意図的に parallel な構造。`manifestType` と
`items` 内のキーのみがモジュール固有。将来統合時の refactor を容易化する設計。

■ 動作の流れ

  [Backup]
  1. userdata_backup_list.csv 読み込み
  2. 管理者権限 + robocopy.exe 存在チェック
  3. 各 entry の SourcePath を環境変数展開、存在確認、種別判定（dir/file）
  4. dry-run summary 表示 + 実行確認（Y/N）
  5. backup/<PcName>/<ts>/entries/<NN>/data/ に robocopy で複製
     ・dir: /E（再帰）or /LEV:1（トップのみ）
     ・file: parent dir 指定 + filename フィルタ
     ・IncludeAcl=1: /COPYALL
     ・ExcludePattern: /XF（file） + /XD（dir）
  6. manifest.json + _restore_notes.txt 書き出し
  7. Post-Apply Verification
  8. New-BatchResult 返却

  [Restore]
  1. userdata_backup_config.csv 読み込み（SourcePcName / BackupTimestamp）
  2. 管理者権限 + robocopy.exe 存在チェック
  3. ソース backup の特定（hostlist 駆動 + 最新 timestamp）
  4. manifest.schemaVersion / manifestType 検証
  5. Restore plan 構築（status='Skipped' エントリ除外）→ 実行確認
  6. 各 entry を robocopy で逆方向に復元
     ・OnConflict=skip: 既存ターゲットは温存
     ・OnConflict=overwrite: そのまま上書き
     ・OnConflict=rename: 既存を .bak_yyyyMMdd_HHmmss にリネーム
  7. Post-Apply Verification（Test-Path で resolvedPath 存在確認）
  8. New-BatchResult 返却

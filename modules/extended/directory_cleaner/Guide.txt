■ 概要
指定したディレクトリの中身を削除、またはディレクトリ自体を削除します。
一時ファイルやキャッシュのクリーンアップに使用します。

■ 前提条件
・管理者権限で実行すること（システム領域の一時ファイル等を削除する場合）
・環境変数を含むパスは Expand-UserEnvironmentVariables により展開される

■ 設定ファイル
[clean_list.csv]
  Enabled     : 有効フラグ（1=実行, 0=スキップ）
  TargetPath  : 対象ディレクトリパス（%LOCALAPPDATA% 等の環境変数使用可）
  Mode        : 削除モード（contents=中身のみ削除 / directory=フォルダごと削除）
  Description : 説明（表示用）
  Segment     : Segment フィルタ（省略可）
                kernel/common.ps1 の Import-ModuleCsv が共通機構として
                自動フィルタするため、モジュール側に追加実装は不要。

[記載例]
  1,%LOCALAPPDATA%\Temp,contents,ユーザー一時ファイル
  1,%WINDIR%\Temp,contents,システム一時ファイル
  0,C:\Logs\OldLogs,directory,古いログフォルダ削除

■ 安全対策（Forbidden Path Whitelist）
スクリプト内で固定のホワイトリスト（forbiddenPaths）を保持し、
C:\、C:\Windows、C:\Program Files、C:\Users、C:\ProgramData、
%USERPROFILE%、%PUBLIC%、fabriq リポジトリ自体のルート等を削除対象から
自動的に除外します。チェックは 3 種類:
  A) 正規化後の完全一致
  B) 対象が禁止パスの親ディレクトリになっていないか
  C) セグメント数 3 未満（例: C:\Users 等）は一律ブロック
CSV 投入時の表示ステップと実行ステップの両方で二重チェックされ、
ブロック対象は [BLOCKED] としてスキップされます。

■ 動作の流れ
1. clean_list.csv を読み込み、対象ディレクトリの存在を確認
2. 削除対象の一覧を表示し、実行確認（Y/N）
3. 各ディレクトリを順に処理（既に空/不在の場合は Skip = 冪等性維持）

■ AutoPilot
AutoPilot モードでは確認をスキップして CSV の設定を自動適用します。

■ 主な用途
不要なアプリのショートカットや不要フォルダの一掃を主目的とします
（例: 全ユーザーデスクトップ C:\Users\Public\Desktop の中身を contents
モードで一掃）。一時ファイル/キャッシュのクリーンアップにも使えますが、
その場合は下記 Verification の注意を参照してください。

■ Post-Apply Verification
削除を実行した項目について「不在」を読み返して検証します（file_delete /
profile_delete と同じ absence oracle）。
  directory モード: フォルダが消えたか（Test-Path == false）
  contents  モード: フォルダは残し中身が空か（子要素ゼロ）
検証対象は実際に削除した項目のみ（Blocked / 不在 / 既に空 の Skip は対象外）。
削除実行がゼロなら Verified 列は空欄（$null）になります。

偽PASS は構造的に発生しません（残ファイルは必ず観測されるため、失敗した削除が
「不在/空」と読まれることはない）。唯一のエッジは、稼働中プロセスが削除直後に
ファイルを再生成する場合（例: 使用中の %TEMP%）で、これは Verified=False に
なり得ますが安全側の偽FAIL であり偽PASS ではありません。
注意: __GATE__ を含む Profile では Verified=False が下流 Order をブロックします。
再生成し得る temp ディレクトリ行を gate 配下に置かないでください。ショートカット
一掃のような再生成の起きない用途では問題ありません。

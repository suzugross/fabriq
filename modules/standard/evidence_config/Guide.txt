■ 概要
PCのシステム情報を収集し、エビデンスとしてテキストファイルおよびCSVに保存します。

■ 設定ファイル
evidence_list.csv（v1.7.0 以降）
  各セクションを収集対象とするか個別に有効/無効を切り替えられます。
  列: Id / Title / Enabled
  Enabled = 1 で収集、0 で当該セクションをスキップします。
  default-on policy: CSV不在 / 該当 Id 行が無い / Enabled が空または不正値 の
  いずれの場合も「有効」として扱います。これにより、CSV を全く編集せずに
  使う限り従来通り全 32 セクション（§01〜§31 + §8b）が収集されます。

  無効化されたセクションは manifest.json 上で
    status = "Skipped"
    reason = "Disabled by configuration (evidence_list.csv)"
  として記録されるため、外部 evidence consumer はこれを intrinsic skip
  （Server-only / バッテリ非搭載 等）と区別できます。
  master log には "[Section XX] Title : Skipped (disabled by configuration)"
  が 1 行グレーで残ります。

  Studio 側では preset.csv により Enabled 列がドロップダウン編集 UI になります。

■ 収集される情報
1. システム基本情報
2. ローカル管理者一覧
3. ネットワーク設定（IP/DNS）
4. プリンター/ポート一覧
5. BitLockerステータス
6. MACアドレス一覧
7. PCシリアル番号（多重ソース収集＋優先順位選定）
   - 全ソースを独立に取得し、canonical SN を優先順位で選定
   - 優先順位: Win32_BIOS.SerialNumber
              → Win32_ComputerSystemProduct.IdentifyingNumber
              → Win32_SystemEnclosure.SerialNumber
              → Registry SystemSerialNumber
   - Win32_BaseBoard.SerialNumber は記録のみ（母板 SN、canonical 候補外）
   - Win32_ComputerSystemProduct.UUID を参考 ID として併記
   - 全ソースの取得値・VALID/INVALID/QUERY FAILED タグを
     10_SerialNumber.txt に記録（OEM 差異の事後監査用）
   - 無効値として "Default string" / "To be filled by O.E.M." /
     "System Serial Number" / "Not Applicable" / 全桁ゼロ等を拒否
8. インストール済みソフトウェア一覧（CSV）
   - デスクトップアプリ（08_DesktopApps.csv）
   - ストア/UWPアプリ（08_StoreApps.csv）
9. ファイアウォール設定（CSV）
   - プロファイル状態（09_FirewallProfiles.csv）
   - ルール一覧（09_FirewallRules.csv）
10. Windows機能の有効/無効一覧（CSV）
   - 10_OptionalFeatures.csv
11. サーバーの役割と機能一覧（CSV）※Windows Serverのみ
   - 11_ServerRolesFeatures.csv
   - Client OSでは自動スキップ
20. System TEMP テキストログバックアップ（セーフティネット）
   - C:\Windows\Temp 直下の .log / .txt を 20_TempBackup\ に退避
   - 非再帰、サイズ上限なし、ロック中ファイルは静かにスキップ
   - 目的: ODT / ドライバ / インストーラ系の原本ログを非常時用に保持
21. Windows ライセンス認証状況（21_WindowsLicense.txt）
   - SoftwareLicensingProduct（CIM）: 製品別 LicenseStatus / PartialProductKey /
     ProductKeyChannel / KMS Machine
   - SoftwareLicensingService（CIM）: ClientMachineID / マシン全体の KMS 設定
   - slmgr /dlv の raw 出力（Installation ID 等を含む診断情報）
22. Office ライセンス認証状況（22_OfficeLicense.txt + 22_OfficeVnextLicenses.csv）
   ※v1.5.0 で vNext per-user スキャン + 自動解釈追加
   - Office には2系統のライセンス機構が併存:
       OSPP (legacy): VL / 買い切り Retail キー（Software Protection Service）
       vNext (現行): M365 サブスクリプション
                     %LOCALAPPDATA%\Microsoft\Office\Licenses\
                     <Category>\<NumericFilename>
                     UTF-16LE JSON、内部 Base64 ライセンス、Microsoft Office
                     Licensing CA で署名済み
   - 22a. C2R レジストリ（ProductReleaseIds / VersionToReport /
     UpdateChannel / Platform / DetectedAsSubscription bool）
   - 22b. OSPP.vbs /dstatus raw（VL/買い切り判定用、引き続き必要）
   - 22c. vNext per-user スキャン（NEW）
       - C:\Users\* 全プロファイル横断走査
       - 各ライセンスファイルを UTF-16LE → 外側 JSON → Base64 内側 JSON
         までデコードし、22_OfficeVnextLicenses.csv に行追加
       - 列: UserProfile / Category / LicenseFile / LicenseType /
              ProductReleaseId / Status / IsTrial / Beneficiary /
              LicenseId / Acid / TenantId / UserId / HardwareIdBound /
              NotBefore / NotAfter / ParseStatus
       - 秘密鍵・Signature 生値・RenewalToken 生値は出力せず、
         HardwareIdBound は (present) フラグのみ
       - TenantId / UserId は audit 上必要なので含める
   - 22d. INTERPRETATION（自動解釈）
       - C2R + OSPP + vNext を突き合わせて以下の verdict を出力:
         * subscription 検出 + Provisioned vNext あり → LICENSED
         * subscription 検出 + vNext 0 件 → "End-user not signed in yet"
         * VL/買い切り + OSPP Grace → 真のアクティベーション失敗
         * VL/買い切り + OSPP Licensed → LICENSED
   - manifest §22 status:
       * Success: subscription + Provisioned あり / VL Licensed /
                  Office 未インストール
       * Partial: subscription + vNext 0 件
                  reason="M365 subscription installed but no Provisioned
                  vNext license found (end-user sign-in pending)"
       * Failed:  VL/買い切り + OSPP Grace
                  reason="OSPP reports Grace/Notifications for non-
                  subscription Office SKU"
   - 既知の挙動: M365 subscription インストーラは OSPP に「飾りキー」
     (例: 末尾 3RQ6B) を残し、サインイン後は更新しないため、OSPP は
     必ず Grace 期限切れ表示になる。これは正常で、22d で「subscription
     検出時の OSPP Grace は EXPECTED」と注記される
23. Security Baseline（23_SecurityBaseline.txt） ※v1.4.0 で追加
   - TPM: Get-Tpm（Present / Ready / Enabled / Activated / Owned /
     ManagedAuthLevel / OwnerAuth 有無 / LockedOut / 製造元 ID）
   - Secure Boot: Confirm-SecureBootUEFI（レガシー BIOS では取得不可
     として記録）
   - VBS / HVCI / Credential Guard: Win32_DeviceGuard（VBS Status /
     SecurityServicesRunning / Configured / CodeIntegrity Enforcement
     Status / AvailableSecurityProperties）
   - LSA Protection: HKLM\SYSTEM\CCS\Control\Lsa\RunAsPPL / RunAsPPLBoot
     （0=Off / 1=On / 2=On + UEFI Lock の意味付き）
   - BIOS / Firmware: Win32_BIOS（Manufacturer / SMBIOSBIOSVersion /
     ReleaseDate / SMBIOS Major.Minor 等。SerialNumber は §10 に統一）
   - 各 probe は inner try/catch で個別退避。1 つが失敗してもセクション
     は Success（取れたものだけ記録）
24. Group Policy Report（24_GroupPolicy.html + 24_GroupPolicySummary.txt）
   ※v1.4.0 で追加
   - gpresult /h を実行して RSoP の HTML を吐く
   - HTML はコンピュータ側 + ユーザー側 RSoP の両方を含む
   - ユーザー側は **本コマンドを実行したユーザー（kitting プロファイル
     の admin01 等）の RSoP** で、最終エンドユーザー視点ではない点に
     注意（コンピュータ側は実 PC 状態なので AD 適用 GPO の証跡として
     有効）
   - サマリ TXT には HTML サイズ・ドメイン参加状態・実行ユーザー名を
     記録（Excel 集計向け）
   - gpresult が exit code 非ゼロまたは HTML 不在なら Failed
   - 実行時間は 5〜30 秒（環境依存。AD 配下で大きい）
25. Certificates（25_Certificates.csv） ※v1.4.0 で追加
   - 4 ストア統合の単一 CSV、Store 列で識別
     LocalMachine\My / LocalMachine\Root / LocalMachine\CA /
     CurrentUser\My
   - 列: Store / Subject / Issuer / Thumbprint / NotBefore / NotAfter /
     HasPrivateKey / EnhancedKeyUsageList / FriendlyName / SerialNumber
   - 秘密鍵そのものは決して出力せず、HasPrivateKey フラグのみ記録
   - 各ストアの列挙が個別失敗しても警告のみで継続
26. Battery Report（26_BatteryReport.html） ※v1.4.0 で追加
   - powercfg /batteryreport /output で HTML を生成
   - DesignCapacity / FullChargeCapacity / 直近の使用履歴 / 推定寿命
     を含む
   - 受入検査で「初期容量 ≧ DesignCapacity の N%」契約条件のエビデンス
     に直結
   - バッテリ非搭載（Win32_Battery 0 件）の場合は Skipped で完結
     （reason="No battery present (desktop PC or battery removed)"）
   - 実行時間は 5〜15 秒

■ 出力先
evidence\pc_information\日付_UID_PC名\
  ・全セクション統合ファイル（_ALL_PC名_Log.txt）
  ・セクションごとの個別ファイル（テキスト形式）
  ・CSV出力（セクションごとのCSVファイル）
  ・20_TempBackup\: System TEMP 直下の .log / .txt 原本
  ・manifest.json: 本収集の機械可読サマリ（後述）

■ manifest.json（v1.3.0 以降）
収集完了時に出力先ディレクトリ直下へ manifest.json を生成します。
スキーマと配置・前方互換ルールは kernel/EVIDENCE_MANIFEST.md（公式契約、
schemaVersion=1）を参照。外部 evidence consumer ツール（fabriq_evidence_manager
等）はこの manifest を起点にエビデンスをパースします。

  - 各セクションの id / title / files / status / reason / elapsedMs を記録
  - status: Success / Skipped / Failed / Partial の 4 値
  - 再実行時は manifest.json.bak に rotate（1 世代のみ保持）
  - manifest 不在の旧 evidence もパーサ側がフォールバックでサポート可能

■ 前提条件
・管理者権限が必要です
  （BitLocker ステータス、ファイアウォールルール一覧、
   Windows Defender 状態、一部のプリンター情報など、
   管理者権限でないと取得できない情報が含まれるため）

■ 使用環境変数 / グローバル変数
本モジュールは以下の変数を参照します（kernel/common.ps1 および
main.ps1 の初期化フローでセットされる想定）。

  $env:SELECTED_NEW_PCNAME
    新しい PC 名が確定済みの場合に使用される PC 名。
    空の場合は $env:COMPUTERNAME（現在のホスト名）をフォールバックとして使用。
    エビデンスの出力フォルダ名・統合ログ名のサフィックスに使用されます。

  $global:FabriqUniqueId
    PC を一意に識別する ID。通常は main.ps1 で Get-HardwareUniqueId により
    事前に算出されている値。未セットの場合はこのモジュール内で
    Get-HardwareUniqueId を直接呼び出してフォールバック取得します。
    出力フォルダ名（日付_UID_PC名）のミドル部分に使用されます。

  $global:FabriqEvidenceBasePath
    セットされていれば、出力先を「統一パス」モードで解決します。
      出力先 = $global:FabriqEvidenceBasePath\pc_information
    （日付・UID・PC名のサブフォルダを作らずフラットに書き出します）
    未セット時はレガシーパス
      <スクリプト>\..\..\..\evidence\pc_information\{日付}_{UID}_{PC名}\
    を使用します。

■ AutoPilot
AutoPilot モードでは確認をスキップしてエビデンス収集を自動実行します。

■ Post-Apply Verification
本モジュールは Post-Apply Verification を実装していません。
エビデンス収集はシステム状態の読み出しのみを行い、設定変更を伴わないため
「適用後の読み返し検証」の概念が適用されません。
New-BatchResult に -Verified は渡していないため、
実行履歴の Verified 列は空欄になります。

■ 動作の流れ
1. 出力先パスを決定（$global:FabriqEvidenceBasePath の有無で分岐）
2. 実行確認（Y/N）
3. 各セクションの情報を順に収集
4. 統合ファイルと個別ファイルに出力

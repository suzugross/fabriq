■ 概要
HKEY_CURRENT_USER（HKCU）配下のレジストリ値を設定・削除するモジュールです。

現ユーザーの HKCU だけでなく、C:\Users\Default\ntuser.dat（新規ユーザー用
Default プロファイル）にも同時に適用することで、このあと作成される
新規ユーザーにも同じ設定が反映されます。必要に応じて Active Setup と
Startup Batch による追加の補完機構も利用できます。

■ 収録スクリプト（module.csv）

[Registry Config (HKCU)]   reg_hkcu_config.ps1
  HKCU と Default プロファイル（HKU:\Hive）の両方に値を書き込み、
  Post-Apply Verification で両方を読み返して検証する。

[Registry Delete (HKCU)]   reg_hkcu_delete.ps1
  HKCU と Default プロファイルから値を削除する。

■ 設定ファイル

[reg_hkcu_list*.csv]（パターン一致で全ファイル自動読み込み）
  Enabled      : 有効フラグ（1=実行, 0=スキップ）
  AdminID      : 管理番号（表示用）
  SettingTitle : 設定タイトル（表示用）
  KeyPath      : レジストリパス（HKEY_CURRENT_USER\... のフルパス）
  KeyName      : レジストリ値の名前（既定値は @）
                 ※ 空欄（または空白のみ）にすると値を作らずキーだけを作成します
                   （reg add "<キー>" /f 相当）。この場合 Type / Value は無視され、
                   HKCU と Default プロファイルの両方にキーが作られます。
  Type         : 型（REG_DWORD / REG_SZ / REG_EXPAND_SZ / REG_QWORD /
                     REG_BINARY / REG_MULTI_SZ）
  Value        : 設定する値
  Segment      : Segment フィルタ（省略可）

  [記載例]
  Enabled,AdminID,SettingTitle,KeyPath,KeyName,Type,Value,Segment
  1,1,タスクバー検索非表示,HKEY_CURRENT_USER\SOFTWARE\Microsoft\Windows\CurrentVersion\Search,SearchboxTaskbarMode,REG_DWORD,0,

■ ファイル分割
`reg_hkcu_list*.csv` に一致するファイルは全て読み込まれ、集約されます。
ジャンルごとに分割して管理できます。
  例: reg_hkcu_list.csv, reg_hkcu_list_ui.csv, reg_hkcu_list_explorer.csv

■ スクリプト内フラグ（先頭で定義）

[reg_hkcu_config.ps1]
  $FORCE_OVERWRITE       (既定: $true)
    $false にすると冪等性チェックが有効になり、現在値と Value が一致する
    エントリは Skip される。$true なら常に上書き。
  $ENABLE_ACTIVE_SETUP   (既定: $false)
    Active Setup 登録（新規ユーザー向け補完機構）の有効化。後述。
  $ENABLE_STARTUP_BATCH  (既定: $false)
    Startup Batch 配置（新規ユーザー向け補完機構）の有効化。後述。

■ HKCU リダイレクト（昇格セッション対応）

Fabriq は管理者権限で動作するため、昇格ユーザーと実際にログオン中の
ユーザーが異なる場合 `HKCU:` が昇格ユーザーのハイブを指してしまいます。
本モジュールは kernel/common.ps1 の `Resolve-HkcuRoot` を用いて
ログオンユーザーの SID を解決し、書き込み先を自動で振り分けます。

  ログオンユーザー = 昇格ユーザー → `HKCU:` を使用
  ログオンユーザー ≠ 昇格ユーザー → `HKU:\<SID>` を使用
  ログオンユーザーのハイブが HKU に見当たらない → Warning 表示後 `HKCU:` で続行

実際の書き込み先は実行開始時に「Current User」または「<username> (via HKU)」
と表示されるので、意図したユーザーに書かれるか確認できます。

■ Default プロファイルへの適用

C:\Users\Default\ntuser.dat を HKU:\Hive として load し、同じ値を書き込みます。
HKCU 書き込み成功 / 失敗に関わらず可能な限り Default 側も更新します。
完了後は必ず HKU:\Hive を unload します（2 回までリトライ）。

これにより、本モジュール実行後に新規作成されるユーザーアカウントは
Default ハイブから値をコピーするため、同じ設定を初期状態で持ちます。

■ Active Setup による新規ユーザーへの補完（$ENABLE_ACTIVE_SETUP=$true のみ）

Default プロファイルへの直接書き込みが反映されないキー（Explorer 側が
ユーザー初期化時に上書きする値など）の補完として使用します。

  動作:
    1. CSV の有効エントリから reg add コマンドを動的生成
    2. C:\ProgramData\fabriq\apply_hkcu.ps1 として配置
    3. common.ps1 の Register-FabriqActiveSetup で HKLM に登録
       → HKLM\SOFTWARE\Microsoft\Active Setup\Installed Components\
         {fabriq-reg-hkcu-config}
    4. 新規ユーザー初回ログオン時に cmd.exe → PowerShell → apply_hkcu.ps1
       が実行され HKCU を書き込む

  注意:
    - HKLM への書き込みのため管理者権限が必須
    - 権限不足時は Warning 表示で Default プロファイル書き込みのみで続行

■ Startup Batch による新規ユーザーへの補完（$ENABLE_STARTUP_BATCH=$true のみ）

Active Setup でもタイミング問題（Explorer 初期化時の上書き）で反映
されないケースの更なる補完として、Explorer 起動後に実行される Startup
ショートカット経由の適用機構を使用します。

  動作:
    1. C:\ProgramData\fabriq\apply_hkcu.ps1 を配置（Active Setup と同内容）
    2. common.ps1 の Deploy-FabriqUserSetupLauncher でランチャー配置
    3. Deploy-FabriqStartupTrigger で Default の Startup フォルダに
       FabriqUserSetup.cmd を配置
    4. 新規ユーザー初回ログオン時:
       Startup → .cmd → フラグチェック（なし）→ PowerShell 起動
       → ランチャー → apply_hkcu.ps1 と apply_spi.ps1 を実行
       → Explorer 再起動
       → %LOCALAPPDATA%\fabriq\user_setup_done.flag を作成
       → Startup から .cmd を自己削除
    5. 2 回目以降のログオン:
       - .cmd が削除済みなら起動しない
       - 残っていてもフラグ検出で即終了（PowerShell は起動しない）

  注意:
    - 配置には管理者権限が必要
    - Active Setup との併用（belt and suspenders）を推奨
    - 初回ログオン時に Explorer が一瞬再起動されます（タスクバーが消えます）

■ 前提条件
・管理者権限が必要です（Default ハイブ load/unload、HKLM 書き込み、
  Active Setup / Startup Batch の配置）
・CSV は UTF-8（BOM 付き）+ CRLF での保存を推奨します（Shift-JIS/CP932 も
  読み込み可能。同梱の reg_hkcu_list.csv は UTF-8 BOM 付きで、BOM による
  ヘッダー読み込み不具合は現行版にはありません）

■ 動作の流れ

  [Registry Config (HKCU)]
  1. HKCU リダイレクト解決（Resolve-HkcuRoot）
  2. reg_hkcu_list*.csv を全件読み込み、Enabled=1 のみ抽出
  3. Default ハイブ load（reg load）→ HKU:\Hive マウント
  4. ドライラン表示（各エントリを [Change] / [Current] で色分け）
  5. 実行確認（Y/N、AutoPilot モードは自動 Y）
  6. 書き込みループ
     6-1. HKCU 側へ書き込み（$FORCE_OVERWRITE=$false なら一致時 Skip）
     6-2. HKU:\Hive 側へ書き込み（同上）
     6-3. HKCU / HIVE 両方の結果から SKIP/SUCCESS/FAIL を集計
  7. Post-Apply Verification
     HKCU と HIVE（load 中の場合のみ）の両方を Test-RegistryValueMatch で
     検証し、$verified（1 件でも失敗なら false）を算出
  8. HKU:\Hive unload（失敗時は 1 回リトライ）
  9. $ENABLE_ACTIVE_SETUP=$true なら Active Setup 登録
  10. $ENABLE_STARTUP_BATCH=$true なら Startup Batch 配置
  11. New-BatchResult -Verified $verified で結果返却

  [Registry Delete (HKCU)]
  Config 同様に Default ハイブを load → HKCU と HIVE の両方から削除 →
  unload。完了後 Active Setup / Startup Batch は扱いません。

■ AutoPilot
両スクリプトとも AutoPilot モードで確認が自動 Y になります。

■ Post-Apply Verification
Config 側のみ実装されています。HKCU と、load 中であれば HIVE の両方を
Test-RegistryValueMatch で検証し、-Verified として返却します。

Delete 側は現在 Verification を実装していません。

■ 冪等性
・Config:  $FORCE_OVERWRITE=$true（既定）では常に上書き、
           $false にすると一致時 Skip。
・Delete:  対象値が既に存在しない場合は Skip。

■ 注意事項
・Active Setup と Startup Batch はともに既定で無効（$false）です。
  新規ユーザーに対する反映強度を上げたい場合のみ有効化してください。
  有効化するとスクリプト冒頭で $ENABLE_ACTIVE_SETUP / $ENABLE_STARTUP_BATCH
  を $true に書き換える運用です。
・Active Setup と Startup Batch が生成する apply_hkcu.ps1 は
  CSV から動的に reg add コマンドを生成します。CSV を更新した場合は
  本モジュールを再実行してスクリプトを再生成してください。
・Active Setup / Startup Batch は HKCU のみの補完機構です。
  HKLM の設定は reg_hklm_config 側で管理してください。

■ 概要
Windows 資格情報マネージャー（資格情報マネージャー / Credential Manager）へ
資格情報を登録するモジュールです。ネイティブの cmdkey.exe を使い、
credential_list.csv に書いた内容を一括登録します。
追加依存はありません（cmdkey は全 Win10/11 に標準搭載）。

対応する資格情報の種別:
  Generic … 汎用（アプリ / Web / サービス全般）
  Domain  … ドメイン パスワード（SMB 共有 / ホスト認証など）
  RDP     … リモートデスクトップ（TERMSRV/ プレフィックスを自動付与）

──────────────────────────────────────────
■ 重要 — 資格情報の保存先（必ず読むこと）
──────────────────────────────────────────
cmdkey は「このモジュールを実行しているアカウント（＝キッティング作業用
アカウント）の vault」にしか書き込めません。各 vault はユーザーごとに
DPAPI で暗号化されているため、後から OOBE 後にログオンする end-user の
vault には届きません。

  ・本モジュールの用途は「キッティング作業中に作業者自身が使う」
    RDP / 共有アクセス等の資格情報を current アカウントに登録すること
    （= kitting-session staging）です。
  ・納品先の end-user の vault へ資格情報を配ることは構造的にできません。
    それが必要な場合は、end-user のコンテキストで実行する別の仕組み
    （Active Setup / RunOnce を end-user として / 初回ログオン時）が
    必要で、本モジュール単体では不可能です。

SYSTEM（NT AUTHORITY\SYSTEM, SID S-1-5-18）で実行された場合は、
対話ユーザーの vault が存在せず書き込んでも無意味なため、
エラーで停止します（dead vault を黙って作らない）。

──────────────────────────────────────────
■ セキュリティ上の注意（監査フリート向け）
──────────────────────────────────────────
cmdkey はパスワードを /pass: 引数としてコマンドラインに渡す仕様のため、
パスワードがプロセス生成監査（Windows イベント 4688 / Sysmon EID 1）に
平文で記録されます。これは registry 書き込みの autologon_config には無い
露出面です。コマンドラインログを取得している B2G フリートでは、
資格情報の平文がセキュリティイベントログ（および evidence バンドル）に
残り得ることを理解した上で使用してください。

  ・ログ出力上はパスワードを必ずマスクします（cmdkey の出力は破棄し、
    本モジュールが手組みのマスク済みメッセージのみ表示）。
  ・credential_list.csv の Password 列は平文です。CSV は機微情報として
    ACL を絞り、git に含めず、キッティング完了後に削除してください。
  ・Import-ModuleCsv の ENC: プレフィックス + マスターパスフレーズによる
    暗号化にそのまま対応します（任意）。

──────────────────────────────────────────
■ 適用後検証（Post-Apply Verification）は非対応
──────────────────────────────────────────
cmdkey は登録済みパスワードを読み返せません（cmdkey /list は target と
user は表示するがパスワード値は一切表示しない）。さらに /list は存在しない
target でも終了コード 0 を返し、問い合わせた target 名を常にヘッダへ
エコーします。このため presence ベースの検証は「古い / 誤ったパスワードが
残っていても PASS」という false PASS を生みます。

したがって本モジュールは適用後検証を実装せず、-Verified は $null を返します
（検証除外リストに登録）。登録の成否は cmdkey の終了コード（0=成功）で
判定し、Success / Partial / Error に集計します。

──────────────────────────────────────────
■ 冪等性
──────────────────────────────────────────
cmdkey /add・/generic は既存の同一 target を無言で上書きします
（last-write-wins、重複なし）。本モジュールは「存在しても常に再登録」
する設計です。スキップ最適化はパスワード一致を確認できない以上、
古いパスワードを温存する危険があるため採用していません。
複数回実行しても最終状態は CSV と一致します。

──────────────────────────────────────────
■ CSV 列（credential_list.csv）
──────────────────────────────────────────
  Enabled     : 1=登録, それ以外=無視
  CredType    : Generic / Domain / RDP（大文字小文字不問）
  TargetName  : 資格情報の target。RDP は素のホスト/FQDN/IP を指定
                （TERMSRV/ は自動付与。既に TERMSRV/ で始まる場合は二重化しない）
  UserName    : cmdkey /user: に渡す。Domain は DOMAIN\user または user@domain
  Password    : 平文パスワード（ログではマスク表示）
  Description : 表示用の説明（任意。空なら TargetName を表示）
  Segment     : セグメント名（任意。Profile からの -Segment 呼び出しで
                一致行と空欄行のみ処理。不要なら列ごと削除可）

不正な行（CredType 不正 / Target・User・Password が空）が 1 件でもあると、
副作用を起こす前に全体をエラー停止します（カタログを直してから再実行）。

出荷時の credential_list.csv は全行 Enabled=0（誤登録防止）。
実際に使う行を 1 にしてください。

──────────────────────────────────────────
■ 種別（CredType）の選び方
──────────────────────────────────────────
  Generic … 汎用。アプリ / Web / サービスが独自に参照する資格情報。
            SMB（ファイル共有）認証には使われない（SMB リダイレクタは
            Generic を参照しない）ので、共有アクセス用途には選ばない。
  Domain  … ドメイン パスワード。Windows 統合認証（SMB / ファイル共有 /
            ホスト認証）用。名前に反して AD ドメインは不要で、WORKGROUP
            （非ドメイン）環境のファイルサーバにもこれを使う。
  RDP     … リモートデスクトップ。target に TERMSRV/ を自動付与。

● WORKGROUP 環境のファイルサーバへ登録する場合
  CredType   : Domain を選ぶ（Generic ではない）。
  TargetName : 接続に使う名前そのものを完全一致で指定する。
                 \\FS01\share          でつなぐなら  FS01
                 \\192.168.1.10\share  でつなぐなら  192.168.1.10
               名前と IP は別の資格情報として扱われるため、両方で繋ぐ運用なら
               2 行に分ける（FQDN 運用なら FQDN を入れる）。
  UserName   : 「サーバ名\ローカルアカウント」形式が確実（例 FS01\backupuser）。
               WORKGROUP はファイルサーバ上のローカルアカウント認証のため、
               サーバ名をプレフィックスにして曖昧さをなくす。
  Password   : そのローカルアカウントのパスワード。

  例（credential_list.csv の 1 行）:
    1,Domain,FS01,FS01\backupuser,P@ssw0rd!,WORKGROUP file server share,

  注: ここで登録した資格情報はキッティング作業用アカウントの vault に入り、
      その作業者が作業中に共有へアクセスする時に使われる（kitting-session
      staging）。納品後に end-user 自身が共有を使うための永続登録は本モジュール
      の対象外（「■ 重要 — 資格情報の保存先」を参照）。

──────────────────────────────────────────
■ sysprep との順序
──────────────────────────────────────────
sysprep /generalize はプロファイルを再生成するため、generalize 前に
登録した資格情報は OOBE 後の end-user プロファイルには引き継がれません。
end-user 向けの資格情報を generalize 前に登録しないでください。

──────────────────────────────────────────
■ 後始末（推奨）
──────────────────────────────────────────
キッティング用アカウントの vault に書いた資格情報は、そのアカウントで
ログオンできる者が平文相当で復元可能です。納品前に、登録した各 target を
cmdkey /delete:<target> で削除するか、キッティング用プロファイルごと
削除してください（credential_list.csv の削除と合わせて実施）。

──────────────────────────────────────────
■ 既知の制限
──────────────────────────────────────────
・パスワードに二重引用符 " を含む場合、Windows PowerShell 5.1 の
  ネイティブ引数引き渡しで正しく渡らないことがあります。
・cmdkey /list の出力はロケール依存（日本語化）のため、本モジュールは
  /list の解析に依存しません（終了コードのみで成否判定）。

■ 概要
バッチファイル（.bat）をCSV定義に従って順に実行します。
タイムアウトや成功判定コードを個別に設定できます。

■ 前提条件
・管理者権限で実行すること（バッチ内の処理が管理者権限を要する場合）
・assets/ フォルダ（またはモジュールフォルダ直下）に実行対象 .bat を配置
  する前提で、相対パスは「モジュールデータルート」基準で解決されます
  （モジュールデータルート = プロファイルデータフォルダ有効時はその
  modules/generic_batch_runner/、無効時はモジュールフォルダ）
・バッチ側で独自に終了コードを返す設計になっていること（SuccessCodes 判定）

■ 設定ファイル
[batch_list.csv]
  Enabled      : 有効フラグ（1=実行, 0=スキップ）
  Description  : 説明（表示用）
  BatchPath    : バッチファイルのパス
                 相対パス = モジュールデータルート基準
                 絶対パス / %TEMP% 等の環境変数も指定可
  Arguments    : 引数（省略可）
  TimeoutSec   : タイムアウト秒数（0 または空欄=無制限）
  SuccessCodes : 成功とみなすExitCode（カンマ区切り、省略時は 0）
  Segment      : Segment フィルタ（省略可）
                 kernel/common.ps1 の Import-ModuleCsv が共通機構として
                 自動フィルタするため、モジュール側に追加実装は不要。

  ※ 旧 Encoding 列は未実装のまま必須列に含まれていたため v1.1.0 で撤去。
     残っていても無視されるので既存 CSV の修正は不要。

[記載例]
  1,初期設定,assets\setup.bat,,60,0,
  1,ドライバー導入,assets\driver_install.bat,/silent,300,"0,3010",
  1,カスタムスクリプト,C:\scripts\custom.bat,,0,,

■ バッチファイルの配置とプロファイル別データオーバーレイ
・相対パスはモジュールデータルートからの相対で解決されます。
  プロファイル実行中にプロファイルデータフォルダ（PDF）が有効な場合、
  batch_list.csv と .bat の両方を PDF 側に置けます。

    profiles/<名前>/modules/generic_batch_runner/
        batch_list.csv
        assets/setup.bat

  PDF 側に該当ファイルが無ければモジュール本体側にフォールバックし、
  その旨が [DATA] 行として警告表示されます（kernel の共通機構）。
・絶対パスも指定可能です（オーバーレイの対象外＝そのまま使われます）。
・バッチの実行時カレントディレクトリはモジュールデータルートです。
  バッチ内で .\ 相対参照をしている場合、PDF 有効時は PDF 側を見ます。
・BatchPath が空欄の行は [NOT FOUND] としてスキップされます。

■ 動作の流れ
1. batch_list.csv を読み込み、ファイルの存在を確認
2. 実行確認（Y/N）
3. 各バッチを順に実行し、ExitCode で成否判定

■ AutoPilot
AutoPilot モードでは確認をスキップして CSV の設定を自動適用します。

■ Post-Apply Verification
本モジュールは Post-Apply Verification を実装していません。
バッチ内部の処理内容はモジュールから観測不能なため、検証は行いません。
New-BatchResult に -Verified を渡していないため、実行履歴の Verified 列は
空欄になります。必要なら各バッチ内で独自の検証ステップを組み込んで
ください。

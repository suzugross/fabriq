■ 概要
タスクバーにピン留めするアプリを設定します。
CSVで定義したショートカット一覧から LayoutModification.xml を動的に生成し、
Default User プロファイルへ配置します。配置後に作成された新規ユーザーに反映されます。

■ 設定ファイル
[taskbar_list.csv]
  Enabled     : 有効フラグ（1=ピン留め対象, 0=スキップ）
  Order       : タスクバー上の表示順序（昇順）
  LinkPath    : アプリのパス（.lnk または .exe）（%APPDATA% 等の環境変数使用可）
  AppId       : アプリケーション ID（省略可の列。DesktopApplicationID として出力）
  Description : 説明（表示用）
  Segment     : Segment フィルタ（省略可）

  ※ 有効行は LinkPath / AppId の「どちらか一方だけ」を記入します。
    両方記入・両方空の行があると Error で停止します（行番号を表示）。
    AppId 列自体が無い旧形式の CSV は、全行 LinkPath 扱いでそのまま動きます。

[記載例]
  Enabled,Order,LinkPath,AppId,Description,Segment
  1,10,,Microsoft.Windows.Explorer,File Explorer,
  1,20,,MSEdge,Microsoft Edge,
  1,30,C:\ProgramData\Microsoft\Windows\Start Menu\Programs\Google Chrome.lnk,,Google Chrome,

■ LinkPath について
以下のいずれかの形式で指定できます。
・ショートカット（.lnk）：スタートメニュー等の .lnk ファイルのパス
・実行ファイル（.exe）：Program Files 等の .exe ファイルの直接パス

ショートカットの格納場所：
・全ユーザー共通：C:\ProgramData\Microsoft\Windows\Start Menu\Programs\
・現在のユーザー：%APPDATA%\Microsoft\Windows\Start Menu\Programs\

■ AppId について
インストールパスに依存しない ID 指定でピン留めできます
（XML の DesktopApplicationID 属性として出力）。
代表的な ID:
・Microsoft.Windows.Explorer : エクスプローラー
・MSEdge                     : Microsoft Edge

注意:
・AppId は実在チェックができません（プレビューでは [PIN:APPID] 表示のみ）。
  指定したアプリが初回ログオン時点で未インストールの場合、Windows は
  エラーを出さずにそのピンだけをスキップします。
・パッケージアプリ（Win11 のメモ帳・電卓等）の AUMID ピン留め
  （taskbar:UWA 要素）には未対応です。必要になったら拡張を検討してください。

■ 存在しないパスについて
LinkPath に指定したファイルが実行時点で存在しない場合、
警告（WARNING）を表示しますが処理は中断せず、XMLにはそのまま記載されます。
キッティングの順序上、後続モジュールでアプリをインストールする場合でも問題ありません。

■ 全件無効（0件）の場合
全エントリを Enabled=0 にして実行すると、空の TaskbarPinList で XML を生成します。
これにより、新規ユーザーのタスクバーからデフォルトのピン留め（Edge 等）も除去されます。

■ 前提条件
・管理者権限が必要です（Default User プロファイルへの書き込みのため）
・既存の LayoutModification.xml は上書きされます

■ AutoPilot
AutoPilot モードでは確認をスキップして CSV の設定を自動適用します。

■ Post-Apply Verification
配置した XML を読み返し、以下の 2 点を検証して -Verified で返します。
・ピンエントリ数が CSV の有効行数と一致すること
・各行の値（LinkPath / AppId、XML エスケープ後の形）が XML 内に存在すること
検証できるのは「XML が意図通り書かれたか」までです。実際にピン留めが
反映されるのは配置後に新規作成されるユーザープロファイルであり、
タスクバー実体の検証は仕組み上できません（AppId 未インストール時の
サイレントスキップも検出対象外）。

■ 動作の流れ
1. taskbar_list.csv を読み込み、Order 昇順でソート
   （各行を LinkPath / AppId のどちらか一方に解決。両方・両方空は Error）
2. LinkPath 行はショートカットの存在確認を行い、対象一覧を表示
   （AppId 行は [PIN:APPID] として存在チェックなしで表示）
3. 実行確認（Y/N）
4. LayoutModification.xml を生成し、Default User プロファイルへ配置
   （属性値は XML エスケープして出力）
5. 配置した XML の内容検証（Post-Apply Verification）
6. 同じ XML を sysprep_config/source/ へ自動コピー（Sysprep ワークフロー用素材）

■ sysprep_config との連携
本モジュールは、生成した LayoutModification.xml を Default User へ配置すると同時に、
modules\standard\sysprep_config\source\LayoutModification.xml へも自動コピーします。
このコピーは無条件で毎回実行され、sysprep_config/source/ ディレクトリが存在しない場合は自動作成します。
コピーに失敗した場合は警告のみ表示し、モジュール全体の結果は Success のまま維持します。

受け取る側の sysprep_config モジュールでは、setupcomplete_list.csv に以下のエントリが
あらかじめ登録されています。
  1,20,CopyFile,LayoutModification.xml,C:\Users\Default\AppData\Local\Microsoft\Windows\Shell\,Deploy taskbar layout,

このエントリにより、Sysprep 実行時に sysprep_config/source/ 内の XML は
C:\Windows\Setup\Scripts\source\ へステージングされ、SetupComplete.cmd から
新規キッティング環境の Default User 配下へ再配置されます。

結果として、taskbar_config を 1 回実行するだけで、
・現環境の Default User への即時反映用パス
・Sysprep 配布用のステージング素材
の 2 箇所が同時に最新化されます。Sysprep ワークフローを使わない場合でも無害です。

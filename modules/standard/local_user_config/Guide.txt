■ 概要
このモジュールには 2 つのスクリプトがあります。

[Create Local Users]
  ローカルユーザーアカウントを作成し、グループへ追加します。

[Delete Local Users]
  ローカルユーザーアカウントを削除します。

■ 設定ファイル

[local_user_list.csv]
  全 PC 共通で作成/削除するユーザーを定義します。
    Enabled                  : 有効フラグ（1=実行, 0=スキップ）
    UserName                 : ユーザー名
    Password                 : パスワード（空欄=パスワードなしで作成。
                               下記「パスワードなしユーザー」参照）
    PasswordNeverExpires     : パスワード無期限（1=無期限, 0=有効期限あり）
    UserMayNotChangePassword : パスワード変更禁止（1=禁止, 0=変更可）
    Group                    : 所属グループ（セミコロン区切りで複数指定可）
    Description              : 説明（表示用）
    Segment                  : Segment フィルタ（省略可）

  [記載例]
    Enabled,UserName,Password,PasswordNeverExpires,UserMayNotChangePassword,Group,Description,Segment
    1,admin_user,P@ssw0rd,1,1,Administrators,管理者ユーザー,
    1,standard_user,Pass1234,0,0,Users,一般ユーザー,
    1,remote_user,R3m0te!,1,1,Users;Remote Desktop Users,リモート接続用,
    1,kiosk_user,,1,1,Users,受付端末用（パスワードなし）,

[local_user_host_list.csv] （任意）
  PC 固有で追加するユーザーを定義します。
  hostlist.csv の NewPCName と一致する行のみが対象に追加されます。
  全 PC 共通ユーザーは local_user_list.csv 側に記載し、こちらは
  PC 名で限定したい追加ユーザーのみを記載します。
    Enabled                  : 有効フラグ（1=実行, 0=スキップ）
    NewPCName                : 対象 PC 名（hostlist.csv の NewPCName と一致）
    UserName                 : ユーザー名
    Password                 : パスワード（空欄=パスワードなしで作成）
    PasswordNeverExpires     : 同上
    UserMayNotChangePassword : 同上
    Group                    : 同上
    Description              : 説明（表示用）
    AutoLogon                : 自動ログオン対象の目印（1=対象, 空/0=対象外・省略可）
                               本モジュールは使いません。autologon_config が
                               __AUTO_to_[HOSTUSER]__ で対象を 1 人に決めるときに
                               参照します（下記「AutoLogon 列」参照）
    Segment                  : Segment フィルタ（省略可）

  [記載例]
    Enabled,NewPCName,UserName,Password,PasswordNeverExpires,UserMayNotChangePassword,Group,Description,AutoLogon,Segment
    1,NEW-PC-01,pc01_local,Pass0001,1,1,Users,PC01 専用アカウント,1,
    1,NEW-PC-01,pc01_admin,Adm00001,1,1,Administrators,PC01 管理者,,

■ AutoLogon 列（自動ログオン対象の指定）

autologon_config のプロファイル行に __AUTO_to_[HOSTUSER]__ と書くと、その PC 用の
ローカルユーザーに自動ログオンします。対象は次の順で絞り込まれます。
  1. NewPCName が選択中の PC 名と一致する行
  2. そのうち Enabled=1 の行
  3. さらに実行中の Segment に一致する行
  4. 残った「その PC の候補」の中だけで AutoLogon 列を見る

候補が 1 人なら AutoLogon 列は不要です。管理者と利用者のように 1 台へ複数作る
場合は、自動ログオンさせたい 1 行に AutoLogon=1 を付けてください。
同じ PC の候補に AutoLogon=1 が 2 人以上あると autologon_config は Error で
止まります（どちらを使うかを現場で選ばせない方針）。
他の PC の行に AutoLogon=1 が付いていても影響しません。PC ごとに 1 行ずつ
AutoLogon=1 を付けるのが通常の書き方です。

本モジュール（Create / Delete Local Users）は AutoLogon 列を読みません。
列が無い古い CSV でもそのまま動きます。
詳細は autologon_config の Guide.txt を参照してください。

■ Group の指定
セミコロン（;）区切りで複数グループを指定できます。
  例: Users;Remote Desktop Users

■ パスワードなしユーザー
Password 列を空欄にした行は、パスワードなしのユーザーとして作成します。
PasswordNeverExpires / UserMayNotChangePassword はパスワードありの行と
同じように反映されます。
  例: 1,kiosk_user,,1,1,Users,受付端末用,

  [入力漏れに注意]
  空欄はすべて「パスワードなし」として扱います。パスワードの書き忘れも
  そのままパスワードなしのアカウントになります。
    ・実行前の一覧に「Password: (none)」と表示されます
    ・作成するときに [WARNING] のログが 1 行出ます
  AutoPilot では確認が出ないため、CSV の段階で確認してください。

  [作成せず失敗にする行]
    ・UserName が空の行（一覧に [INVALID] と表示）
    ・行が途中で切れていて Password の欄そのものが無い行
      （例: 「1,user01」で終わっている行。空欄の「1,user01,,...」とは別扱い）
  どちらも、同じ名前のユーザーが既に居るかどうかに関係なく失敗になります。

  [制約]
    ・既存ユーザーは SKIP です。あとから Password を空欄に書き換えても、
      既に在るアカウントのパスワードは変わりません。
    ・Windows の既定（空のパスワードの使用をコンソール ログオンのみに制限）
      では、パスワードなしのアカウントはリモート デスクトップや共有フォルダー
      への接続に使えません。
    ・autologon_config の __AUTO_to_[HOSTUSER]__ は、パスワードなしの
      ユーザーを対象にできません（Error で止まります）。
    ・パスワードの最小文字数などのポリシーが効いている PC（ドメイン参加機
      など）での動作は未確認です。作成できなかった場合はその行だけ失敗に
      なります。

■ 動作モード

  [全 PC 共通モード]
  local_user_host_list.csv が存在しない、または SELECTED_NEW_PCNAME が
  未設定の場合、local_user_list.csv の内容のみを処理します。

  [PC 固有マージモード]
  local_user_host_list.csv が存在し、かつ SELECTED_NEW_PCNAME と一致する
  行があれば、それらを共通ユーザー一覧に追加して処理します。

  [PC 固有単独モード]
  local_user_list.csv が空 (ヘッダのみ) または Segment フィルタで全行が
  対象外となった場合でも、local_user_host_list.csv 側にマッチする行が
  あればそれだけで処理を続行します。逆に、両側とも 0 行になった場合は
  Skipped で正常終了します (ファイルそのものが見つからない場合のみ
  Error 終了)。
  Profile で create / delete などの Segment 別運用を行うときに、
  共通ユーザーを置かず PC 個別ユーザーのみを host_list.csv 側で
  Segment 区別する運用をサポートします。

■ 動作の流れ

  [Create Local Users]
  1. local_user_list.csv を読み込む
  2. local_user_host_list.csv が存在すれば NewPCName で突合して追加
  3. Enabled=1 のユーザーを一覧表示（Enabled=0 は [DISABLED] 表示）
     ・Password: (set) / (none) を表示。作成できない行は [INVALID]
  4. 実行確認（Y/N）
  5. ユーザー作成
     ・UserName が空 / Password の欄が無い行は作成せず失敗
     ・既存ユーザーは SKIP（冪等性あり）
     ・Password 空欄の行はパスワードなしで作成
     ・PasswordNeverExpires / UserMayNotChangePassword を反映
     ・AccountNeverExpires は常に true で作成
  6. Group 列のグループへ Add-LocalGroupMember で追加
  7. Post-Apply Verification で各ユーザーの存在とグループ所属を検証

  [Delete Local Users]
  1. local_user_list.csv を読み込む（Enabled フィルタなし＝全行対象）
  2. local_user_host_list.csv が存在すれば NewPCName で突合して追加
  3. 削除対象ユーザーを一覧表示
  4. 実行確認（Y/N）
  5. ユーザー削除
     ・存在しないユーザーは SKIP

■ AutoPilot
AutoPilot モードでは確認をスキップして CSV の設定を自動適用します。

■ Post-Apply Verification
Create Local Users のみ実装しています。
適用後、Get-LocalUser でユーザーの存在を確認し、
Get-LocalGroupMember で Group 列の各グループへの所属を検証します。
結果は -Verified で返却されます。
Delete Local Users は検証ステップを持ちません。

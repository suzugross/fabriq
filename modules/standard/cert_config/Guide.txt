■ 概要
証明書ファイル（.pfx/.p12/.cer/.crt）を Windows の証明書ストアにインポートします。
certs/ ディレクトリに配置した証明書を、CSVで定義したストアにインポートします。

2つの動作モードがあります：
・明示指定モード（AutoRoute=0）: CSVでストアを直接指定してインポート
・自動振り分けモード（AutoRoute=1）: PFX内の証明書をCA/Client別ストアに自動振り分け

■ 設定ファイル
[cert_list.csv]
  Enabled      : 有効フラグ（1=実行, 0=スキップ）
  FileName     : certs/ 内のファイル名（環境変数・ワイルドカード使用可）
  StoreScope   : ストアスコープ（LocalMachine / CurrentUser）※AutoRoute=1時は空欄可
  StoreName    : ストア名（My / Root / CA / TrustedPublisher 等）※AutoRoute=1時は空欄可
  Password     : PFXパスワード（ENC:暗号化対応）。.cer/.crt は空欄
  AutoRoute    : 自動振り分け（1=ON, 0または空=OFF）
  Overwrite    : 上書き制御（1=既存を置換, 0=既存ならスキップ）
  FriendlyName : フレンドリ名（PFXのClient証明書に設定。省略可）
  Description  : 説明（表示用）
  Segment      : セグメントフィルタ（省略可）

[記載例]
  1,ca-root.cer,LocalMachine,Root,,0,0,,ルートCA証明書,
  1,%SELECTED_NEW_PCNAME%_*.p12,,,ENC:xxxx==,1,1,,PC別クライアント証明書,
  1,codesign.pfx,LocalMachine,TrustedPublisher,ENC:yyyy==,0,0,Code Signing CA,コード署名証明書,

■ 証明書ファイルの配置
certs/ ディレクトリに証明書ファイルを配置してください。
対応形式: .pfx, .p12（秘密鍵付き）, .cer, .crt（公開鍵のみ）

■ PC名による自動マッチ
FileName に環境変数とワイルドカードを使用できます。
例: %SELECTED_NEW_PCNAME%_*.p12
  → 環境変数を展開後、ワイルドカードで certs/ 内を検索し最初にマッチしたファイルを使用

■ AutoRoute（自動振り分け）モード
AutoRoute=1 を指定すると、PFX内の全証明書を自動的に振り分けます。
・CA証明書（BasicConstraints CA=true）→ LocalMachine\Root
・クライアント証明書（それ以外）    → LocalMachine\My
複数証明書（ルートCA＋中間CA＋クライアント）が入ったPFXに対応しています。

■ パスワード
PFXファイルにはパスワードが必要です。
・ENC: プレフィックスで暗号化パスワードを記載可（Fabriq Studioで暗号化）
・平文での記載も可
・.cer/.crt ファイルはパスワード不要（空欄）

■ 前提条件
・管理者権限が必要です（LocalMachine ストアへの書き込みには必須）
　- 本スクリプトは Test-AdminPrivilege の明示チェックは持ちませんが、
　  LocalMachine ストアへの書き込み時に PowerShell 側で ACCESS_DENIED
　  となり失敗します。管理者権限で起動された Fabriq から呼び出してください。
・CertificateAuthority（CA 判定）を評価するため .NET の X509 API を使用します
・CSVのエンコーディングは Shift-JIS（ANSI）で保存してください

■ AutoPilot
AutoPilot モードでは確認（Confirm-ModuleExecution）をスキップして
CSV の設定を自動適用します。AutoRoute=1 の行も確認なしで振り分けインポートされます。

■ AutoRoute モードと PC 名連携（詳細）
FileName 列で環境変数展開 + ワイルドカードを併用できます。
Fabriq 起動時に選択したホストの PC 名（SELECTED_NEW_PCNAME）を使って
「その PC 用のクライアント証明書」だけを自動適用する運用が可能です。

  [例]
    FileName: %SELECTED_NEW_PCNAME%_*.p12
    AutoRoute: 1
    Password: ENC:xxxx==

  [動作]
    1. %SELECTED_NEW_PCNAME% → "NEW-PC-01" 等に展開
    2. certs/ 内を "NEW-PC-01_*.p12" でワイルドカード検索
    3. 最初にマッチしたファイルを採用（見つからなければ [NOT FOUND]）
    4. PFX 内の全証明書を Basic Constraints の CA フラグで判定
       ・CA 証明書   → LocalMachine\Root
       ・クライアント → LocalMachine\My（FriendlyName も設定）

これにより hostlist ベースで「PC ごとに異なるクライアント証明書」を
展開する運用が可能になります（証明書ファイルは事前に certs/ へ配置）。

■ Password 列と暗号化（ENC: プレフィックス）
Password 列は以下の 3 形式に対応します。
・平文             : そのまま記述（例: MyPass123）
・ENC: プレフィックス : Fabriq Studio で暗号化した文字列を記述
                    （例: ENC:AAECAwQFBgc...==）
・空欄             : .cer / .crt ファイル用（パスワード不要）

ENC: 形式は Import-ModuleCsv 側で自動復号されます。
Fabriq Studio の "Encrypt Password" 機能で生成した文字列をそのまま
貼り付けてください。平文パスワードを CSV に保存したくない場合に使用します。

■ Post-Apply Verification
インポート後にストア内を読み返して、サムプリントが存在するか検証します。
- 検証手段: Test-CertificateInStore（X509Store.Certificates をサムプリントで検索）
- 対象: 実際にインポート／既存維持した全証明書
- 全件が検証成功した場合 $verified=$true、1 件でも失敗すれば $false
- AutoRoute モードでは PFX 内の各証明書を個別に検証
- 結果は New-BatchResult の -Verified パラメータで返却されます

■ 使用環境変数
- $env:SELECTED_NEW_PCNAME : FileName のワイルドカード展開で使用（PC 名連携）
- $env:SELECTED_SEGMENT    : Segment フィルタ（Import-ModuleCsv が暗黙参照）
- その他 %ENV% 形式の任意環境変数も FileName 列で展開可能

■ 動作の流れ
1. cert_list.csv を読み込み、有効な行を抽出
2. 各証明書の状態を確認し、対象一覧を表示（[IMPORT]/[SKIP]/[REPLACE]等）
3. 実行確認（Y/N）後、証明書をインポート
4. インポート後、ストア内のサムプリントで存在検証（Post-Apply Verification）

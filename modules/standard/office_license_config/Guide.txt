====================================================
Office License Config - Guide
====================================================

■ 概要
Microsoft Office のプロダクトキー登録とライセンス認証を行うモジュールです。
以下の2つのスクリプトと1つの共通ヘルパーで構成されます。

  office_license_install.ps1 : プロダクトキーの登録 (cscript OSPP.vbs /inpkey)
  office_license_auth.ps1    : ライセンス認証の実行   (cscript OSPP.vbs /act)
  _office_common.ps1         : 共通関数 (Find-OsppVbs)


■ OSPP.vbs パスの自動検出
Office のアーキテクチャ（32bit/64bit）とインストール方式（C2R/MSI）に応じて
以下の順序で OSPP.vbs を自動検出します。

  優先度1: C2R 64bit  %ProgramFiles%\Microsoft Office\root\Office16\OSPP.vbs
  優先度2: C2R 32bit  %ProgramFiles(x86)%\Microsoft Office\root\Office16\OSPP.vbs
  優先度3: MSI 64bit  %ProgramFiles%\Microsoft Office\Office16\OSPP.vbs
  優先度4: MSI 32bit  %ProgramFiles(x86)%\Microsoft Office\Office16\OSPP.vbs

  ※ C2R（Click-to-Run）は Office 365/2019/2021/2024 の標準形式です。
  ※ MSI はボリュームライセンスのレガシー形式です。
  ※ Office16 は Office 2016/2019/2021/2024/365 で共通のディレクトリ名です。


■ CSV 強制指定（ハイブリッド方式）
特殊な環境では office_key.csv の OsppPath 列にフルパスを記載することで
自動検出を上書きできます。通常は空欄のままで問題ありません。

  例: OsppPath = C:\CustomOffice\Office16\OSPP.vbs


■ office_key.csv の列定義

  Enabled        : 有効フラグ (1=実行, 0=スキップ)
  ProductKey     : XXXXX-XXXXX-XXXXX-XXXXX-XXXXX 形式
                   ENC: プレフィクスによる暗号化に対応
  ActivationType : MAK または KMS
                   MAK = Microsoft Activation Key（インターネット認証）
                   KMS = Key Management Service（社内サーバー認証）
  OsppPath       : OSPP.vbs のフルパス（空欄=自動検出）
  Description    : 説明（表示用）
  Segment        : セグメント名（空欄=全セグメント共通）


■ ActivationType による動作の違い

  [MAK]
    - 認証時にインターネット接続が必要
    - office_license_auth.ps1 の Pre-flight で疎通チェックを実行
      1. Test-NetConnection activation.sls.microsoft.com -Port 443 (TCP)
      2. 失敗時 → Test-Connection 8.8.8.8 (ping フォールバック)
      3. ping 成功 → Warning を出して続行（プロキシ環境想定）
      4. 両方失敗 → Error で中断
    - プロダクトキー1つにつき1回の認証でアクティベーション完了

  [KMS]
    - 社内 KMS サーバーへの到達性のみが必要（インターネット不要）
    - 疎通チェックはスキップされる
    - 定期的な再認証（180日）が自動的に行われる


■ 使用例

  [キー登録]
    1. office_key.csv に Enabled=1 でプロダクトキーと ActivationType を設定
    2. メニューから "Install Office Product Key" を実行

  [認証]
    1. メニューから "Activate Office License" を実行
    2. MAK の場合はインターネット疎通チェックが自動実行される
    3. 全製品が LICENSED になっていれば自動スキップ（冪等）


■ 複数製品への対応
Office 本体、Visio、Project など複数のプロダクトキーを
office_key.csv の別行に定義できます。
認証スクリプト（/act）は全製品を一括で認証します。


■ 前提条件
・管理者権限が必要です（Test-AdminPrivilege で自動チェック）
・Office（C2R または MSI）がインストール済みで OSPP.vbs が存在すること
・MAK の場合は activation.sls.microsoft.com:443 への HTTPS 到達性
  （ping 8.8.8.8 で代替可能なプロキシ環境にも対応）
・KMS の場合は社内 KMS サーバーへの到達性


■ AutoPilot
AutoPilot モードでは確認をスキップして CSV の設定を自動適用します。
install / auth の両方とも Confirm-ModuleExecution を経由します。


■ Post-Apply Verification
[office_license_install.ps1]
  プロダクトキー登録の検証を実装しています。/inpkey の ExitCode は信頼できない
  （エラーでも 0 を返す）ため、適用後に /dstatus を読み返し、登録キー末尾 5 文字が
  存在するかを照合します。New-BatchResult に -Verified（$true=適用キー全件確認 /
  $false=1 件以上欠落 / $null=読み返し対象なし）を渡します。

[office_license_auth.ps1]
  適用後に cscript OSPP.vbs /dstatus を再実行し、全製品の
  LICENSE STATUS を再解析して LICENSED 状態を検証します。
  現時点では Status / Message で結果を返しており、New-ModuleResult に
  -Verified は渡していません（/dstatus 解析による事実上の検証は
  スクリプト内で完結しています）。


■ 使用環境変数
  ProgramFiles        : C2R 64bit / MSI 64bit の OSPP.vbs 検索に使用
  ProgramFiles(x86)   : C2R 32bit / MSI 32bit の OSPP.vbs 検索に使用


■ 冪等性チェック（office_license_auth.ps1）
/dstatus 出力から全製品の LICENSE STATUS を解析し、
LICENSED 以外のステータス（OOB_GRACE, UNLICENSED, NOTIFICATION,
EXTENDED GRACE 等）が1つでも存在する場合のみ認証を実行します。
全製品が LICENSED であれば Skipped を返します。


■ トラブルシューティング

  [OSPP.vbs not found]
    Office がインストールされていないか、非標準パスにインストールされています。
    office_key.csv の OsppPath 列でフルパスを明示指定してください。

  [ProductKey is still encrypted (ENC:)]
    マスターパスフレーズが入力されていない状態で
    ENC: 暗号化キーを使用しています。

  [Invalid key format]
    XXXXX-XXXXX-XXXXX-XXXXX-XXXXX（ハイフン含め29文字）の形式を確認してください。

  [No internet connectivity for MAK activation]
    TCP 443 および ping 8.8.8.8 の両方に失敗しています。
    - ネットワークケーブル / Wi-Fi 接続を確認してください。
    - ファイアウォールで ICMP と HTTPS が許可されているか確認してください。

  [TCP 443 failed, ping succeeded (proxy warning)]
    プロキシ環境でアクティベーションサーバーへの直接接続がブロックされています。
    - WinHTTP プロキシ設定を確認してください: netsh winhttp show proxy
    - 認証自体はプロキシ経由で成功する可能性があります。

  [Activation failed]
    - MAK: インターネット接続とプロダクトキーの正当性を確認してください。
    - KMS: KMS サーバーへの到達性を確認してください。
    - プロダクトキーとインストール済み Office のエディションが一致しているか確認してください。


■ Security Note: ProductKey の Win32_Process.CommandLine 露出
（Microsoft プラットフォーム構造的制約）

office_license_install.ps1 は OSPP.vbs `/inpkey:KEY` を cscript 経由で
呼び出します。このとき ProductKey が cscript.exe の起動引数として
OS layer に展開され、以下のログ機構に記録されます:

  - Win32_Process.CommandLine（cscript.exe の lifetime 中、live snapshot）
  - Windows Security Log Event ID 4688（site で `Audit Process Creation`
    + `IncludeCommandLine` が有効な場合、永続記録 → SIEM 転送先まで到達）
  - PowerShell Module Logging（site で有効化された場合）

これは fabriq 側で回避できない **Microsoft プラットフォームの構造的制約**
です。理由:
  - OSPP.vbs は WScript.Arguments 経由で `/inpkey:KEY` を positional
    引数として受け付ける設計
  - stdin / file / 環境変数経由の代替インターフェイスが存在しない
  - Office C2R 2019/2021/365 では `OfficeSoftwareProtectionService`
    WMI provider が deprecated/削除済で、CIM 直叩きの clean 経路が
    存在しない（MSI Office 2016 以前なら CIM 経由可能だが、現代の
    B2G 環境ではほぼ C2R）
  - 自前 wrapper VBS / Process.Start native API 等の代替案も、
    最終的に OSPP.vbs に `/inpkey:` を引数として渡す経路を回避
    できないため、leak vector を閉じられない

[B2G / 厳格監査環境での運用推奨]
本制約が問題となる環境（Audit Process Creation + IncludeCommandLine
が site policy で強制有効、SIEM 転送あり）では、以下のいずれかを
検討してください:

  1. Office Customization Tool (OCT) で生成した XML 設定に ProductKey
     を埋め込み、Office インストール時に同時に key 登録する
     （install 時 1 回の暴露で post-install の再 key install 不要に）
  2. Microsoft Volume Licensing Service Center で AD 連携 KMS / ADBA
     を構成し、ProductKey の手動登録を完全に省略する
  3. 上記が不可能な場合、本モジュールの実行時間帯のみ
     IncludeCommandLine を一時的に無効化（GPO ロールバック付き）

[fabriq の他モジュールとの対比]
  - windows_license_config: SoftwareLicensingService CIM 経由で実装、
    ProductKey は CIM パラメータとして渡るため Win32_Process.CommandLine
    に現れない（Windows License は安定 WMI provider あり）
  - robocopy_config (v1.0.1+): UNC AuthPass を stdin pipe 経由で net.exe
    に渡すことで Win32_Process.CommandLine 露出を回避（v1.0.0 では
    暴露していた、kernel 3.2.5 期に修正）
  - office_license_config: OSPP.vbs の制約により上記対策が適用不可

詳細は `project_crypto_security_review.md` メモリの A3 T1-B office
セクションを参照。Microsoft platform 改善（Office C2R に新しい license
API が追加される等）があれば再評価対象。

■ 手動確認コマンド

  ライセンス状態の確認:
    cscript "C:\Program Files\Microsoft Office\root\Office16\OSPP.vbs" /dstatus

  プロダクトキーの登録:
    cscript "C:\Program Files\Microsoft Office\root\Office16\OSPP.vbs" /inpkey:XXXXX-XXXXX-XXXXX-XXXXX-XXXXX

  ライセンス認証:
    cscript "C:\Program Files\Microsoft Office\root\Office16\OSPP.vbs" /act

  ※ パスは環境に応じて読み替えてください。
